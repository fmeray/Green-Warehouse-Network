# Green Warehouse Network

This project implements the `Green Warehouse Network: Final Spec`: a deterministic Germany-wide warehouse planner with a primary and backup for every customer, normal and single-site-failure capacity constraints, and CO₂ or cost optimization.

The static inputs are in `data/`: 24 customers, 12 candidate sites, and diesel/electric emission factors. The solver reads prepared OpenRouteService distances from cache and never calls a routing API at run time. If a cache is unavailable, it uses the documented haversine × 1.3 estimate and reports that provenance in the dashboard.

## Scenario API

The six structured functions are in `src/tools.py`: `get_baseline`, `list_sites`, `validate_scenario`, `run_scenario`, `simulate_failure`, and `compare_scenarios`.

`run_scenario({})` runs only the main CO₂ scenario. The scenario defaults include `max_backup_km=500`, `k_sweep=false`, and `compare_objectives=false`.

Use `k_sweep: true` to solve the requested k curve for k = 2 through 5. Use `compare_objectives: true` to solve both objective variants and return the cost of avoiding CO₂ in EUR per tonne when both CBC solves are optimal. Every solve reports CBC status and its 1% relative gap.

The only optimization backend is PuLP 2.9.0 with its bundled CBC solver. If CBC is unavailable, the application returns a clear solver error; it does not select another solver or search method.

## Run

Python 3.10+ is required.

```bash
python3 -m pip install -r requirements.txt
python3 -c "from src.tools import run_scenario; print(run_scenario({})['status'])"
streamlit run app.py
```

The dashboard opens with a customer-only map, blank KPI cards, and no solver result. Choose CO₂ or cost in the sidebar and confirm it before the agent can run anything. After confirmation, the LangGraph agent uses the OpenAI structured intent parser and LangChain tool-calling interface to launch `run_scenario`; subsequent chat messages describe scenario changes. Set `OPENAI_API_KEY` and `OPENAI_MODEL` in `.env` before using it. If the key is missing or an OpenAI call fails, the error is shown in chat and no parser or solver fallback is used. The Streamlit session supplies one graph `thread_id`, and clarification turns resume with LangGraph `Command` values.

Warehouse closures are entered in the scenario chat; the agent returns the tool-backed before/after impact, including CO₂ and cost changes, instead of using a separate failure view. The dashboard provides Map, k curve (after a k-sweep), and Scenarios views. Its report is generated by the LLM from the confirmed objective and all scenario/tool events in the current session, then can be downloaded as HTML. It does not send email or expose a web API.

Run the tests with:

```bash
python3 -m unittest discover -s tests -v
```
